# Working in Still core

This is `EffortlessMetrics/still-core`, the public producer of `@effortlessmetrics/still`. Read [the README](README.md) and [design and ownership](docs/design.md) for package, starter and consumer boundaries. Keep private consumer source and assets outside this repository. Preserve frozen fixtures, licensed notices and published history. Publication and deployment require their separate authorization described in [release preparation](docs/release.md).

Verify the actual checkout, candidate and continuing work owner before changing files. Reconcile the latest scope and holds from their sources, and coordinate overlapping writers through the existing task or PR. Keep the working session, installed dependencies and build caches when compatible with the candidate and supported Node version. Reinstall or rebuild when changed inputs or a required procedure warrant it.

Choose local checks for the changed behavior using `package.json` and the focused routes in [the upgrade proof](docs/thin-starter-upgrade-proof.md). New source files require an explicit `source-files.json` entry and `node scripts/audit-boundary.mjs`. Complete required checks and approvals. The checked-in [Verify Still workflow](.github/workflows/verify.yml) qualifies PR heads and main pushes; composed merge-queue qualification is the desired direction and is not deployed here. Verify current workflow and repository gates before integration.

Challenge concrete remaining failure cases. When another agent is needed for independent review, use a subagent inside the working session, preserving warm context and the candidate. Do not assume optional `ub-review` capacity or transfer review to another environment. Preserve valid earlier reviews and actual required reviews; additional passes should resolve a specific question.

Before reset or handoff, update the existing durable task or PR record with the continuing owner, latest scope and holds, checkout commit/tree and dirty state, changes, exact commands/results, accessible evidence locations and hashes where applicable, remaining work and blockers. Distinguish completed, denied, pending and uncertain operations; check an uncertain outcome before retrying. Keep unreviewed session records outside the public source tree. Preserve the candidate until recovery evidence is readable by the receiver.

Bind evidence to the candidate and subject that actually ran. Label earlier results with their original identity and explain what still applies; refresh evidence affected by changed inputs without replaying unaffected optional proof. Never label carried-forward results as a current-candidate run or use them to bypass required fresh checks. Delivery creation alone is not qualification: CI adds `CI-QUALIFICATION.json` to the retained delivery only after the existing checks succeed. It records the observed checkout, workflow subject, run, runtime and delivered hashes; it does not establish hosted readiness or publication. Preserve the exact archive and receipt together as required by release preparation.
