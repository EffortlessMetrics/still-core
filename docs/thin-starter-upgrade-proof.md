# Actual thin-starter upgrade proof

`npm run verify:upgrade` is an additive producer regression. It requires installed core development dependencies and a Playwright Chromium browser, uses fresh temporary directories outside the workspace, and removes those directories on completion. CI installs the declared Playwright browser. `STILL_BROWSER_EXECUTABLE` can select an existing local Chromium; identify its version when reporting results.

The fixture is the complete public `EffortlessMetrics/still` tree at `952251c914088b31ba9fc514966266442bb30956`, including its offline 0.1.4 and AstroMache 0.2.6 deliveries, editable policy, consumer source, fonts, notices and license verifier. `tests/fixtures/thin-upgrade/PROVENANCE.json` records the source commit/tree, SHA256 of the Git source archive, and SHA256 of every source file. Verification authenticates the archive, exact regular-file inventory and every file before extraction. No sibling checkout, GitHub fetch, private consumer source or historical Git history is required at verification time. Denied pre-split Still PR4 is excluded.

Historical Still 0.2.0 is recreated by `npm pack --ignore-scripts --json` from the exact public `packages/still` blobs at `21c42f4923ca7b000517bea2903b13e107c334ac`. The fixture records both source-file hashes and archive SHA256 `5945258a0a0a69f21a87424c1d3d488ae97cbdb6420e574940dd72e4f54ff3c6`. This hash **does not match** the accepted business archive `feface4f62bbadfc41458e31d3cec453541675eef15ca37fca9d6c31ef272be2`. This regression establishes public source compatibility, not acceptance of a business upgrade or equivalence to its archive.

The verifier first repins the frozen actual starter to that historical public archive. It clones this baseline for a frozen 0.2.1 relocation control, then packs the current 0.2.2 producer package and upgrades only the Still dependency, its delivery receipt and lock entries. All unrelated manifest/lock entries and consumer files must stay unchanged. Previous archives are retained; the current pack receives a distinct `-upgrade.tgz` file identity. Neither archived 0.2.1 bytes nor historical 0.2.0 bytes are overwritten.

All three consumers run `npm ci --ignore-scripts`, independent archive/lock/installed-byte validation for all three vendored dependencies, type/build checks, the starter's license verifier and license tests, and the browser suite. The runtime package file allowlist, every export's bytes and all 0.2.0/0.2.1 runtime source bytes are compared. The browser snapshot records actual content, computed styles and geometry at 1440, 390 and 320 pixels for all six pages. The frozen 0.2.0-to-0.2.1 control still requires entire build trees, including digest-derived worker bytes, to match. For 0.2.2, every component except Layout retains its exact historical runtime bytes, and the existing CSS prefix remains unchanged; only the opt-in divider rules are appended. Layout is authenticated against the entire historical source with exactly one reviewed write-fallback operator changed from `||` to `??`, preserving a valid empty storage key. A reference build temporarily restores the authenticated historical Layout in the installed archive, leaving all other candidate inputs intact. The strict historical-source and CSS-only output guards apply to that reference; no script bytes are stripped or normalized. The installed production Layout is restored after either reference success or failure and rebuilt, and its full output inventory and every byte must match the production snapshot taken before the reference build. Default-page content, computed styles and geometry must match. Reference-build HTML may change only the exact content-hashed stylesheet URL; every unrelated emitted asset remains byte-identical. The output-digest worker and receipt must regenerate. Receipt resource/byte/HTML totals and every worker body digest are independently recomputed from emitted files; receipt URLs, worker policy/program and all unrelated output remain identical after normalizing only the exact stylesheet URL/body digest, dependent HTML digests and revision. The same real browser cache/body-digest checks remain required. `verify:contract` additionally proves both historical missing-divider controls and current opt-in appearance, JavaScript independence and class removal across light/dark and 1440/390/320px, while default columns/cards/footer/actions/prices remain unchanged.

Browser acceptance covers themes, system preference and unavailable storage; the minimal packed consumer additionally exercises omitted, explicit undefined, custom and empty storage keys on both historical and current packages, requiring the historical empty-key failure and repaired persistence; keyboard navigation and skip-link focus; responsive offers and action geometry; disabled contact without a send action; natural worker activation and control on the next navigation; offline reading, fonts and every precached asset's body digest; offline fallback focus; reconnect freshness; hover/focus intent prefetch and save-data/slow/offline restrictions. The local test server preserves emitted body bytes and adds a monotonically increasing response header. Reconnect must return a newer network header than the verified cached document, so visible cached text alone cannot pass the reconnect assertion. The tests never force worker activation or control.

The application remains `UNLICENSED`. Original template MIT/Apache notices, dependency grants and separate font OFL notices are preserved. `verify:packed` continues to qualify the historical exporter and portable fresh delivery; `verify:upgrade` qualifies the frozen public thin-starter snapshot identified above. Both commands run in core CI. These results do not qualify later starter commits or branded consumers, or establish hosted readiness, registry publication, deployment or consumer integration approval.

Normal-network tests provide deterministic connection hints before the application's scripts run; save-data, slow-connection and offline restrictions have separate assertions. Real registration, activation, worker control and offline fetches remain browser-owned.

The byte-preserving local server redirects slashless directory requests to the trailing-slash URL before serving index.html, retaining the encoded query and correct relative-asset base. Run `node --test tests/serve-thin-upgrade.test.mjs` for the small HTTP contract regression (redirect/query encoding, relative asset resolution, direct index responses, freshness and missing-route 404s); it requires no consumer install or build. This checks the integration server, not service-worker behavior.

Encoded slash aliases are canonicalized before serving directories or explicit files, so nested relative resources resolve against the same path segments used for filesystem lookup. Other path escapes and the serialized query (including duplicate keys, plus signs and an empty marker) remain intact. The focused HTTP regression covers malformed/double encoding, missing resources and redirect-host/backslash controls. The browser regression uses a private ephemeral server and synthetic emitted HTML/SVG/script bytes to check actual image and script resolution through encoded nested directory and index aliases. It extends the HTTP integration proof; it does not alter or qualify a new offline worker, precache policy or consumer archive.

Repeated internal separators, including mixed literal and encoded slashes, redirect to a single separator before serving directory, index or asset responses. Redirect-host guards reject leading host paths and host paths exposed by URL dot-segment normalization before collapsing slashes. Internal separators collapse before final URL normalization so parent segments agree with filesystem resolution. HTTP regressions preserve serialized query bytes and missing-route 404s; a browser regression loads a root-level relative image and a page-local script through repeated-slash directory and index aliases, including an encoded parent-segment case. This prevents a successful document response from hiding a broken relative-resource base.

Reference qualification preserves build errors unchanged. If both phases fail, an AggregateError retains the reference error first and the production restoration error second; a failed restoration never reports qualification success. Cleanup errors are also retained. Run "node --test tests/layout-runtime-delta.test.mjs" for inert build-adapter controls covering clean restoration, each single failure and both failures. These controls exercise installed Layout and output restoration without starting npm, Astro or a browser; real build and browser qualification remains required in CI.

Reference preparation copies production and historical Layout files into a temporary directory beside the installed Layout before replacing it with a same-filesystem rename. Interrupted preparation writes leave the installed production source and output intact, so the call can be retried after the write fault clears. Restoration renames the complete saved production file back before rebuilding; it needs no new data write. If that rename fails, the error retains the filesystem cause and identifies the saved production file in `recoveryLayout` and its message. Preserve that file, recover it to the reported installed path, and rebuild production successfully before retrying. A failed production build can leave partial output and must never be treated as qualified. Abrupt process termination and concurrent qualification of the same consumer are not covered by this helper. Run `node --test tests/layout-reference-writes.test.mjs` for injected partial-write and rename controls, retained-backup recovery, and an actual local npm build that emits partial reference output before failing. These synthetic builds require no dependency installation; CI still qualifies real Astro and browser behavior.
