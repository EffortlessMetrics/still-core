# Actual thin-starter upgrade proof

`npm run verify:upgrade` is an additive producer regression. It requires installed core development dependencies and a Playwright Chromium browser, uses fresh temporary directories outside the workspace, and removes those directories on completion. CI installs the declared Playwright browser. `STILL_BROWSER_EXECUTABLE` can select an existing local Chromium; identify its version when reporting results.

The fixture is the complete public `EffortlessMetrics/still` tree at `952251c914088b31ba9fc514966266442bb30956`, including its offline 0.1.4 and AstroMache 0.2.6 deliveries, editable policy, consumer source, fonts, notices and license verifier. `tests/fixtures/thin-upgrade/PROVENANCE.json` records the source commit/tree, SHA256 of the Git source archive, and SHA256 of every source file. Verification authenticates the archive, exact regular-file inventory and every file before extraction. No sibling checkout, GitHub fetch, private consumer source or historical Git history is required at verification time. Denied pre-split Still PR4 is excluded.

Historical Still 0.2.0 is recreated by `npm pack --ignore-scripts --json` from the exact public `packages/still` blobs at `21c42f4923ca7b000517bea2903b13e107c334ac`. The fixture records both source-file hashes and archive SHA256 `5945258a0a0a69f21a87424c1d3d488ae97cbdb6420e574940dd72e4f54ff3c6`. This hash **does not match** the accepted business archive `feface4f62bbadfc41458e31d3cec453541675eef15ca37fca9d6c31ef272be2`. This regression establishes public source compatibility, not acceptance of a business upgrade or equivalence to its archive.

The verifier first repins the frozen actual starter to that historical public archive. It clones this baseline, then packs the current producer package and upgrades only the Still dependency, its delivery receipt and lock entries. All unrelated manifest/lock entries and consumer files must stay unchanged. Previous archives are retained; the current pack receives a distinct `-upgrade.tgz` file identity. Neither archived 0.2.1 bytes nor historical 0.2.0 bytes are overwritten.

Both consumers run `npm ci --ignore-scripts`, independent archive/lock/installed-byte validation for all three vendored dependencies, type/build checks, the starter's license verifier and license tests, and the browser suite. The runtime package file allowlist, every export's bytes and all 0.2.0/0.2.1 runtime source bytes are compared. The browser snapshot records actual content, computed styles and geometry at 1440, 390 and 320 pixels for all six pages. Entire build trees, including digest-derived offline worker bytes, must match.

Browser acceptance covers themes, system preference and unavailable storage; keyboard navigation and skip-link focus; responsive offers and action geometry; disabled contact without a send action; natural worker activation and control on the next navigation; offline reading, fonts and every precached asset's body digest; offline fallback focus; reconnect freshness; hover/focus intent prefetch and save-data/slow/offline restrictions. The local test server preserves emitted body bytes and adds a monotonically increasing response header. Reconnect must return a newer network header than the verified cached document, so visible cached text alone cannot pass the reconnect assertion. The tests never force worker activation or control.

The application remains `UNLICENSED`. Original template MIT/Apache notices, dependency grants and separate font OFL notices are preserved. `verify:packed` continues to qualify the historical exporter and portable fresh delivery; `verify:upgrade` qualifies the frozen public thin-starter snapshot identified above. Both commands run in core CI. These results do not qualify later starter commits or branded consumers, or establish hosted readiness, registry publication, deployment or consumer integration approval.

Normal-network tests provide deterministic connection hints before the application's scripts run; save-data, slow-connection and offline restrictions have separate assertions. Real registration, activation, worker control and offline fetches remain browser-owned.
